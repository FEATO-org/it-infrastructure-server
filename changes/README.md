# ユーザー向け変更記録

プレイヤーやサービス利用者が認識できる変更を行ったら、実装経路に関係なく `changes/pending/` に記録する。Skill 経由、直接修正、Codex、手動修正のいずれにも同じ基準を適用する。判断基準はファイル種別や変更方法ではなく、利用者から見た最終的な影響とする。

## 記録が必要な変更

- 新機能・新コンテンツの追加、既存機能の仕様変更、不具合修正
- バランス、アイテム、Mob、権限、利用条件の変更
- メッセージ、UI、表示内容の変更
- 設定や依存関係の更新によって、利用者から見た挙動が変わるもの

内部リファクタリング、整形、コメント、テスト、CI/CD、開発環境、内部ログ、外部仕様が変わらない依存関係更新だけなら記録は不要。ユーザー影響が微妙な場合は記録を作る。何が変わるか、または理由を事実として書けない場合は、推測で埋めずユーザーに確認する。

## ファイルと形式

`changes/pending/<descriptive-name>.md` に、変更内容を識別できる短い kebab-case の名前で追加する。利用者にとって意味のある変更を簡潔に書き、秘密情報や未確認の効果を含めない。

```yaml
---
category: improvement
scope: ancient-coin
change: 古銭にエンチャント光沢を常時表示するようにしました。
reason: 通常の金塊系アイテムと見分けにくかったためです。
---
```

`category` は `feature`、`content`、`balance`、`improvement`、`fix`、`system`、`breaking` から選ぶ。`scope` は対象を表す短い kebab-case、`change` は利用者から見た具体的な変更事実を1行で書く。`reason` は任意で、確認できた変更理由がある場合だけ1行で書く。本文や他のフィールドは追加しない。ファイル名は英小文字・数字・ハイフンによる kebab-case にする。

リリース手順は [パッチノート運用](../docs/patch-notes.md) を参照する。
